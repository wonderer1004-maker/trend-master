# Trend Guard V2 — 조건검색·백테스트·자동 모의매매

이 버전은 수익을 보장하는 최종 전략이 아니라, 기존 검사의 체결 가정을 개선한 검증 후보입니다. 증권사 실주문 기능은 없습니다. 매일 조건검색과 가상 주문·잔고 재계산을 자동 실행합니다.

## 기존 결과 분석
기준자금 1천만원, 2024~2026.09 구간:
|전략|누적수익률|연환산|최대낙폭|승률|거래수|
|---|---:|---:|---:|---:|---:|
|R1 강세돌파·보합현금|11.75%|4.13%|-2.12%|57.89%|19|
|R2 강세눌림·보합반등|5.90%|2.11%|-9.99%|27.78%|144|
|R3 강세혼합·보합반등|14.14%|4.94%|-10.62%|30.13%|156|

R1은 낮은 낙폭이 장점이지만 표본이 19회로 작습니다. R3의 추가수익은 2.38%포인트에 불과한 반면 최대낙폭은 약 5배입니다. 보합 매매를 늘리는 것이 유리하다는 근거가 부족합니다. 현재 생존 대형주 10개만 검사했고 시장 대비 초과수익 검증도 없으므로 전종목 최고의 조건검색식으로 일반화할 수 없습니다.
기존 코드는 당일 종가에서 추세 이탈을 확인하면서 같은 종가에 청산합니다. 장 마감 후 판단해서 주문하는 운영 방식이라면 다음 시가로 바꿔야 합니다. 새 전략의 실적은 기존 결과와 별도로 확인해야 합니다.

## 조건검색식 — 모두 AND
시장: 코스피 종가 > 200일선×1.02, 50일선 > 200일선, 200일선 > 20거래일 전 200일선.
종목: 종가 > 50일선 > 150일선 > 200일선, 150일선 상승.
유동성: 20일 평균 거래대금 50억원 이상.
상대강도: 종목 60일 수익률 > 코스피 60일 수익률.
변동성: ATR14 / 종가 ≤ 5%.
돌파: 종가 > 전일까지의 60일 최고가.
거래량: 당일 거래량 ≥ 전일까지 20일 평균 거래량×1.5.
추격제한: 종가 ≤ 20일선×1.12.

보합·약세·200일 데이터 미충족 시 신규매수하지 않습니다. 약세 전환은 기존 보유도 다음 시가 청산합니다. MIXED 후보는 강세에서 20일선 재돌파와 평균 이상의 거래량도 허용합니다. 두 후보의 성과를 비교하며 자동으로 성과 좋은 후보로 변경하지 않습니다.

HTS 조건검색은 위 조건으로 후보를 추리고, 시장 필터·상대강도·ATR·수량 계산은 Python에서 최종 확인합니다. 이 문서는 영웅문에 가져오는 ACS/CTS 파일이 아닙니다. 관리종목·거래정지·투자경고·상장기간·업종 정보 필터는 현재 Yahoo 데이터에 없으며 실전 연결 전에 증권사 데이터로 추가해야 합니다.

## 매매·위험 규칙
종가 확정 신호 → 다음 거래일 시가 가상매수. 전일 종가 대비 ±3% 초과 시가 갭은 매수 취소.
초기손절 거리 = max(매수가의 4%, ATR14×2). 8% 초과면 거래 제외.
거래당 초기 위험 ≤ 평가자산의 0.5%, 총 초기 위험 ≤ 2.5%.
최대 5종목, 종목당 20%, 총 투자 80%; 잔여 현금 유지.
수량 = floor(min(위험예산/손절거리, 종목한도/비용포함매수가, 가용현금/비용포함매수가)).
보유 중 최고가−ATR×3으로 손절을 높이고, 오늘 높인 손절은 다음 날부터 적용.
50일선 이탈·약세 전환·60거래일 보유 → 다음 시가 청산.
고점 대비 계좌 −8% 또는 전일 대비 −2%이면 보유종목 다음 시가 청산 예약.
고점 대비 −8% 이후 신규매수는 잠금 상태. 운용자가 분석한 뒤 새로운 모의매매 기간으로 재시작해야 합니다. 손절은 갭·하한가에서 손실을 보장하지 않습니다.
레버리지·물타기·공매도는 구현되어 있지 않습니다.

Python 3.11에서:
```
pip install pandas==2.2.3 numpy==2.2.6 yfinance==0.2.65
python -m unittest discover -s tests -p test_trend_guard_v2.py -v
python scripts/trend_guard_v2.py
```
GitHub Actions → Trend Guard V2 research and paper execution → Run workflow.
평일 한국시간 17:10 예약 실행. GitHub 예약 실행은 지연될 수 있으므로 실시간 장중 주문용이 아닙니다.
`reports/trend_guard_v2/comparison.csv`: 두 후보×두 구간×기본/2배비용 비교.
`reports/trend_guard_v2_latest/signals.csv`: 최신 완결 일봉 조건검색.
`*_paper_state.json`: 가상잔고·최근 가상주문. 매번 같은 데이터에서 재현하는 replay 방식으로 실제 주문은 전송하지 않습니다.
입력 CSV를 쓰려면 `--data-dir 경로`: ^KS11.csv와 10개 종목 CSV, 첫 열 날짜, open/high/low/close/volume 열. 가격 조정 방식과 통화를 동일하게 맞춰야 합니다.

## 수익성 통과 기준과 미완료 영역
수익률뿐 아니라 코스피 가격지수 대비 초과수익, MDD, 거래수, 비용 두 배 민감도를 확인합니다. 코스피 비교는 배당 미포함 가격지수여서 총수익 비교의 대체가 아닙니다. 2024~2026 구간은 이미 본 결과라 진정한 미사용 검증 구간이 아닙니다. 2026.10 이후 새 기간과 전종목 과거 구성원·상폐종목 데이터가 필요합니다.
실전 승인 후보 기준: 새 미사용 구간 순수익 양수, 비용 두 배에도 순수익 양수, 시장 대비 위험조정성과 개선, 충분한 거래표본, 모의매매 60거래일 동안 중복주문·잔고불일치 0건. 이 기준은 성과를 보장하지 않습니다.
현재 매매비용은 매수/매도 각각 수수료 0.1%+슬리피지 0.1% 또는 각각 0.2%+0.2% 가정입니다. 실제 증권사 수수료·매도세·호가단위·거래정지·부분체결을 따로 검증해야 합니다.

실제 자동매매 연결에는 계좌 인증, 실시간 시세, 가용예수금 조회, 주문/체결 확인, 부분체결·취소·재접속, 영구 주문 ID와 중복 방지, 재시작 시 잔고 동기화가 필요합니다. 키움 공식 REST API가 모의/실전 환경을 제공하지만 이 버전에는 인증정보와 증권사 어댑터가 없어 계좌 연결은 아직 완료되지 않았습니다. 비밀키를 GitHub 파일이나 채팅에 입력하지 마세요.
